# 江淮汽车（600418）涨跌新闻归因 —— 执行计划

## 目标

把 600418 历史上"明显涨跌"的交易日，与当日前后的新闻/公告对上，给出**可核查的归因**，而不是事后编故事。

## 核心风险（必须先探）

**东财接口在这台机器上已全线失联**（`tools/probe_eastmoney.py` 记录：连续 5 次 `RemoteDisconnected`）。akshare 的个股新闻主力正是东财（`stock_news_em` / `stock_info_global_em`），**大概率同样不通**。所以第一步不是写归因逻辑，是先探哪条源能活。

备选源：新浪（`stock_info_global_sina`）、同花顺（`stock_info_global_ths`）、财联社（`stock_telegraph_cls`）、巨潮公告（`stock_zh_a_disclosure_report_cninfo`）、东财个股新闻（`stock_news_em`）。

## 步骤

### 步骤 0：接口探针（`probe_akshare.py`）
逐个函数用**子进程 + 超时**跑（akshare 内部不设 timeout，直接调会挂死）。记录：能否返回、条数、字段结构、覆盖的日期范围。

> 硬要求：每个接口单独子进程，超时 90s 强杀，避免一个卡死拖垮全场。

### 步骤 1：本地行情取涨跌事件（不依赖网络）
用 `qlib_data/cn_data_2026` 的 600418 日线（close + factor），自己算日收益：
- 阈值：`|·| ≥ 5%` 记为**明显涨跌**（另存 `≥3%` 的次级档）；
- 额外标注：**涨跌停**（±10%）与**放量**（成交量 > 20 日均量 1.5 倍）；
- 输出 `events.csv`：日期、收盘、收益率、是否涨跌停、量比、事后 5 日累计。

> 行情用本地 bin，不走网络——本地数据是已校验过的 2026-10-28 版，比 akshare 的实时接口更稳。

### 步骤 2：抓新闻并对齐
对每个事件日，取 **T-1 ~ T+2** 窗口的新闻：
- 个股新闻（标题 + 发布时间 + 来源 + 链接）；
- 全市场快讯（可能含"江淮"字样）；
- 巨潮公告（600418 正式公告，最硬的证据）。

### 步骤 3：归因
规则先筛（标题含"江淮/JAC/轻型车/新能源"等实体词），再由我（LLM）逐条判读并归类：
`新产品/合作/销量/订单` | `业绩/财报` | `股东行为/回购/减持` | `政策补贴` | `市场/行业` | `传闻/无关`。
每条事件输出：**归因类别 + 一句话理由 + 证据链接 + 置信度（高/中/低）**。

### 步骤 4：产出
```
projects/jac_600418/news_attribution/
├── PLAN.md            ← 本文件
├── probe_akshare.py   ← 接口探针
├── fetch_news.py      ← 新闻抓取（带本地缓存，失败可续跑）
├── attribute.py       ← 事件→新闻对齐 + 归因
├── news_cache/        ← 原始 JSON 缓存
├── events.csv         ← 涨跌事件表
├── news_matches.csv   ← 事件↔新闻匹配表
└── REPORT.md          ← 归因报告
```

## 纪律

- **不把相关性当因果**：没有直接证据的写"疑似/时间吻合"，不写"因为"。
- **数字全部来自实际输出**，禁止凭印象编新闻标题或涨跌幅。
- 接口不通就如实报不通，不拿"行业通用逻辑"凑数。
- 缓存优先：抓一次存本地，后续重跑不重复请求。
- 不写任何数据/代码进 `cn_data_2026`（只读）。

**核心结论**：能归因的只有三成；证据率由数据可得性决定（2026-04 起有新闻 → 94.1%）；公告本身平均定价效应极弱（T1 超额多在 ±0.5%）；真正的大波动由"预期"驱动（合作传闻 / 产品质量事故 / 监管介入）。
